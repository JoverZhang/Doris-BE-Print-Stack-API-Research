# OceanBase kill -60 x86_64 stack collection research

## Question

Research the OceanBase CE v4.5.0 implementation behind `kill -60 <observer-pid>`,
with focus on the x86_64 stack collection path and its libunwind dependency.

## Scope

- `repos/source/oceanbase-v4.5.0_CE/src/observer/ob_signal_handle.*`
- `repos/source/oceanbase-v4.5.0_CE/deps/oblib/src/lib/signal/*`

## Executive Summary

- `kill -60` is handled by a dedicated `SignalHandle` thread, not directly by
  the kernel signal handler. Startup blocks signal 60 in the process, the
  thread waits with `sigtimedwait()`, and case 60 calls
  `send_request_and_wait(VERB_LEVEL_1, current_tid)` when ASAN is off.
- The collection is two phase. A worker thread enumerates `/proc/self/task/`,
  sends `SIGURG` to each target tid with `SYS_rt_tgsigqueueinfo`, waits for the
  target thread to prepare its stack string in the signal handler, writes that
  string from the worker, then releases the target.
- On x86_64, each target's `prepare()` calls OceanBase `safe_backtrace()`. That
  wrapper calls upstream libunwind local APIs: `unw_getcontext`,
  `unw_init_local`, repeated `unw_step`, `unw_get_reg(UNW_REG_IP)`, and
  `unw_is_signal_frame`.
- Build contracts matter. `oblib` is compiled with `-fno-omit-frame-pointer`.
  x86_64 links `${DEP_DIR}/lib/libunwind.a`. The dependency set pins a
  `devdeps-libunwind-static-1.6.2...x86_64.rpm`. `OB_USE_ASAN` disables the
  signal-60 stack collection branch.
- Adjacent `faststack()` launches an external `obstack` binary and writes
  `stack.<pid>.<timestamp>`, but `kill -60` does not call `faststack()` in this
  source snapshot.
